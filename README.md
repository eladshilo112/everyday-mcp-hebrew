# everyday-mcp-hebrew

פתרון MCP קטן, שימושי ובטוח לכל יום.

המטרה פשוטה: לקחת בעיות אמיתיות מחיי היום יום ולהפוך אותן לכלים פתוחים שעובדים עם Claude Code, עם Codex ועם כל לקוח MCP תקני.

כל פתרון במאגר הוא:

* מקומי כברירת מחדל, ללא איסוף מידע וללא טלמטריה
* קטן מספיק כדי להבין, לשנות ולהפעיל לבד
* מתועד קודם בעברית, עם הוראות באנגלית לפי הצורך
* כולל שרת MCP, קוד, בדיקות ודוגמת שימוש אמיתית
* עובר בנייה, בדיקות, בדיקת סודות ובדיקת מבנה לפני פרסום

## הפתרון הראשון

### 001, מארגן משימות וסדר יום

מדביקים רשימת משימות חופשית בעברית או באנגלית, מציינים כמה זמן פנוי יש, ומקבלים סדר יום פשוט לפי דחיפות, משך המשימה וסדר קבוע וברור.

הכלי לא ניגש ליומן, לא שולח הודעות ולא משנה קבצים. הוא רק מנתח את הטקסט שהועבר אליו ומחזיר תוצאה.

```text
קלט:
דחוף לשלוח את הטופס היום, 20 דקות
לקנות חלב, 15 דקות
להכין מצגת למחר, שעה

זמן פנוי: 75 דקות
התחלה: 09:00
```

```text
09:00 עד 09:20, דחוף לשלוח את הטופס היום
09:20 עד 09:35, לקנות חלב

לא שובץ: להכין מצגת למחר, אין מספיק זמן פנוי
```

[הוראות מלאות והתקנה](solutions/001-task-organizer/README.md)

## קטלוג

כל הפתרונות מופיעים ב־[CATALOG.md](CATALOG.md). כל תיקייה יומית עצמאית וכוללת את כל מה שצריך להפעלה.

## איך האוטומציה היומית עובדת

בכל יום בשעה 09:00 לפי `Asia/Jerusalem`:

1. Claude יוצר תכנית מוגבלת לפתרון יומי חדש.
2. Codex מייצר שינוי כטלאי מוגבל לתיקיית הפתרון החדשה ולקטלוג.
3. רץ שער קבוע שאינו נשלט בידי המודלים: בדיקות מבנה, רשימת תלויות מותרת, TypeScript, בדיקות MCP וסריקת סודות.
4. רק תוצאה שעברה את כל השערים נפתחת כ־Pull Request.
5. המיזוג האוטומטי יכול להתרחש רק לאחר שבדיקת ה־CI הנדרשת עוברת.

האוטומציה נכשלת באופן סגור אם אחד מסודות ההפעלה חסר. היא לעולם אינה מריצה פקודות מעטפת שהוחזרו כטקסט בידי מודל.

## בדיקה מקומית של כל המאגר

נדרשים Python 3.11 ומעלה, Node.js 20 ומעלה ו־npm.

```bash
python scripts/validate_catalog.py
python -m unittest discover -s tests -v
python scripts/validate_solution.py solutions/001-task-organizer --install
```
