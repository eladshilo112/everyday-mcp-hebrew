# בודק מבנה קובצי CSV

שרת MCP מקומי שמאתר מרכאות שבורות, מספר עמודות לא אחיד וכותרות ריקות או כפולות. הדוח מציג קודים ומיקומים בלבד. תוכן תאים, שמות כותרות וקטעי מקור אינם מוחזרים.

בדיקה מוצלחת מאשרת את מבנה הקובץ בלבד. היא אינה מאשרת נכונות נתונים, התאמה עסקית או בטיחות נוסחאות ביישום שאליו מייבאים.

## הכנה והרצה

נדרש Node.js בגרסה 20 ומעלה. התלויות מוצמדות ב־package.json. אין חשבון, טלמטריה או פעילות רשת בשרת. שלב הכנת התלויות עשוי לדרוש גישה למאגר חבילות; בסביבה מנותקת יש לספק אותן מראש. קובץ נעילת חבילות אינו כלול, והמאמת הקבוע יפיק אותו ללא lifecycle scripts.

לאחר הכנת התלויות בסביבת הבדיקה:

```sh
npm run check
npm run build
npm test
node dist/src/server.js --root /absolute/path/to/csv-folder
```

השורש חייב להיות תיקייה מקומית מוחלטת, מפורשת וקיימת. אין ברירת מחדל ואין גישה לתיקיות אחרות. ב־Windows משתמשים למשל ב־`C:\CSV`. ללא שורש תקין התהליך מסתיים בקוד 1, עם הודעה קבועה ל־stderr. stdout שמור להודעות MCP.

## חיבור ללקוחות MCP

Claude Desktop ולקוחות המשתמשים ב־mcpServers יכולים לקבל הגדרה כזו. יש להחליף את הנתיבים בנתיבים מוחלטים למחשב שלכם:

```json
{
  "mcpServers": {
    "csv-structure-checker": {
      "command": "node",
      "args": ["/absolute/path/to/009-csv-structure-checker/dist/src/server.js", "--root", "/absolute/path/to/csv-folder"]
    }
  }
}
```

ב־Claude Code אפשר לרשום את אותה פקודת stdio:

```sh
claude mcp add csv-structure-checker -- node /absolute/path/to/dist/src/server.js --root /absolute/path/to/csv-folder
```

ב־Codex, בהגדרות MCP המקומיות:

```toml
[mcp_servers.csv_structure_checker]
command = "node"
args = ["/absolute/path/to/dist/src/server.js", "--root", "/absolute/path/to/csv-folder"]
```

ב־Windows בתוך JSON יש להכפיל לוכסנים אחוריים, למשל `C:\\CSV`. אין צורך במפתח API או במשתני סביבה סודיים.

## הכלי check_csv_structure

```json
{"path":"example.csv","delimiter":"comma","header":true,"max_findings":200}
```

| פרמטר | משמעות |
|---|---|
| path | נתיב יחסי לקובץ רגיל בתוך השורש, חובה |
| delimiter | comma, semicolon או tab. ברירת מחדל comma |
| header | האם הרשומה הראשונה מכילה כותרות. ברירת מחדל true |
| max_findings | מספר שלם בין 1 ל־200. ברירת מחדל 200 |

אין ניחוש מפריד או קידוד. UTF-8 תקין עם BOM אופציונלי בלבד. פענוח פגום, סימון UTF-16 או תווי NUL מחזירים UNSUPPORTED_ENCODING. קידוד אחר שבמקרה מורכב מבתי UTF-8 תקינים אינו ניתן לזיהוי ודאי ללא מידע חיצוני.

## כללי הפענוח והדוח

הרשומה הלוגית הראשונה קובעת את מספר העמודות, גם כאשר header=false. הכותרות מושוות בדיוק, ללא הסרת רווחים, שינוי אותיות או נרמול Unicode. כותרת ריקה חוזרת יכולה להפיק גם EMPTY_HEADER וגם DUPLICATE_HEADER, באותו סדר.

מרכאות עוטפות מותרות רק בתחילת שדה. בתוך שדה כזה מפרידים ושורות חדשות הם תוכן, ושתי מרכאות רצופות מייצגות מרכאה אחת. לאחר מרכאה סוגרת מותרים רק מפריד, סיום שורה או סוף קובץ. נתמכים LF ו־CRLF, כולל בתוך שדה מצוטט. CR בודד הוא שגיאת תחביר BARE_CR.

סיום שורה אחרון אינו יוצר רשומה נוספת. שורה ריקה פנימית מחוץ למרכאות היא רשומה עם שדה ריק אחד. קובץ ריק או BOM בלבד מחזיר EMPTY_FILE, אפס רשומות ו־expected_columns=null. קובץ כותרת בלבד כולל רשומה אחת ואפס רשומות נתונים.

| שדה בתוצאה | משמעות |
|---|---|
| ok | true רק אם כל הבדיקה הושלמה ללא ממצאים |
| complete | האם הפענוח והדיווח הושלמו עד סוף הקובץ |
| status | complete, syntax_error, resource_limit או error |
| records_completed | רשומות שפוענחו במלואן, כולל כותרת |
| data_records | רשומות שהושלמו ללא הכותרת, אם הוגדרה |
| expected_columns | מספר העמודות ברשומה הראשונה שהושלמה, או null |
| findings | קוד, record, line ו־field כשמתאים. ללא ערכי תאים |
| error | קוד עצירה או כשל, או null כשהבדיקה הושלמה |

מספרי רשומות, שורות ושדות מתחילים ב־1. EMPTY_FILE משתמש ב־record=0 ו־line=1. COLUMN_COUNT מפנה לשורת תחילת הרשומה. ממצא כותרת מפנה לשורת תחילת השדה. שגיאת תחביר מצביעה על השורה והשדה שבהם זוהתה, ושדה שלא נסגר מצביע על מיקום סוף הקובץ. שגיאות כמות כוללות expected ו־actual.

הפענוח נעצר בשגיאת המרכאות הראשונה. הרשומה הפגומה אינה נספרת כרשומה שהושלמה. קודים: BARE_QUOTE, AFTER_CLOSING_QUOTE ו־UNTERMINATED_QUOTE. ממצאים קודמים נשמרים בסדר הקובץ. כאשר מכסת הממצאים מלאה ושגיאת תחביר מתגלה, קוד העצירה עדיין מופיע ב־error, אך הממצא הנוסף אינו נכנס למערך.

## מגבלות קשיחות

| משאב | גבול כולל |
|---|---|
| בתים בקובץ, כולל BOM | 5 MiB, כלומר 5,242,880 בתים |
| רשומות לוגיות, כולל כותרת | 100,000 |
| שדות ברשומה | 1,000 |
| גודל תוכן שדה לאחר הסרת מרכאות התחביר | 256 KiB בבתי UTF-8 |
| ממצאים בתשובה | 200 לכל היותר, לפי max_findings |

גודל השדה סופר מרכאה כפולה שפוענחה כבית אחד, ו־CRLF כשני בתים. החריגה מזוהה בזמן הקריאה או הפענוח. אין הסתמכות על גודל הקובץ המדווח בלבד. בקריאה נבדק לכל היותר בית אחד מעל מגבלת הקובץ כדי לזהות חריגה.

קודי העצירה הם FILE_BYTES_LIMIT, RECORD_LIMIT, FIELD_COUNT_LIMIT, FIELD_BYTES_LIMIT ו־FINDINGS_LIMIT. הגעה בדיוק לגבול מותרת. FINDINGS_LIMIT מופיע רק כאשר יש ממצא נוסף שלא נכנס, ואז הפענוח נעצר. הספירות מתארות רק את הרשומות שהושלמו עד העצירה, ואינן אומדן לכל הקובץ. שגיאת קידוד או גישה מתרחשת לפני הפענוח ומחזירה אפס רשומות.

## גישה לקבצים ובטיחות

נדחים נתיבים מוחלטים בקלט הכלי, traversal, קישורים, junctions, reparse points, נתיבי UNC, ADS, שמות התקנים ונתיבים עמומים עם נקודה או רווח בסוף רכיב. נבדקים גם אבות השורש. קבצים מיוחדים ותיקיות אינם מתקבלים כקובצי CSV.

ב־Windows מתבצעת בדיקת FileAttributes.ReparsePoint באמצעות PowerShell המובנה, עם סקריפט קבוע, ללא פרופיל וללא שילוב הקלט בקוד. כשל בבדיקה חוסם את הקריאה. הכונן אינו יכול להיות כונן רשת ממופה. הבדיקה אינה מבצעת התקנות, שינוי הגדרות או הרצת תוכן הקובץ.

בדיקות נתיב וזהות מתבצעות לפני פתיחה, לאחר פתיחה ולפני החזרת התוצאה. שינוי מזוהה מחזיר FILE_CHANGED. אין כאן snapshot אטומי של מערכת הקבצים: יש לבחור שורש מהימן ולהימנע משינויים מקבילים או גישה של גורם עוין לתיקייה בזמן הבדיקה. המימוש הנייד של Node אינו מבטיח הגנה מפני כל מרוץ החלפת ספריות. READ_ERROR מציין כשל קריאה כללי, PATH_REJECTED נתיב חסום, ו־NOT_REGULAR_FILE קלט שאינו קובץ רגיל.

השרת אינו משנה קבצים, מתקן נתונים, מפעיל פקודות מתוך CSV או שומר יומני תוכן. אין חותמות זמן או אקראיות בתוצאה. אותה סדרת בתים ואפשרויות מחזירה אותה תוצאה בסביבה יציבה. structuredContent ותוכן הטקסט מכילים את אותו JSON. annotations מגדירים קריאה בלבד, ללא הרס, פעולה חוזרת וללא עולם חיצוני.

## דוגמאות ובדיקות

תיקיית examples מכילה קבצים סינתטיים בלבד. אפשר להפעיל את השרת כאשר תיקייה זו היא השורש ולבדוק את valid-hebrew.csv, את semicolon.csv עם delimiter=semicolon, ואת broken.csv כדי לראות שגיאת מרכאות.

חמישה קובצי בדיקות מכסים תחביר ומיקומים, מגבלות כולל גבולות מדויקים, קידוד ונתיבים, עשר הערכות קבועות ותקשורת stdio אמיתית. בדיקת האינטגרציה מאתחלת לקוח SDK, מגלה את הכלי ומפעילה אותו כאשר ממשקי הרשת של Node חסומים. בדיקה נוספת בוחנת מסגרות JSON-RPC ואת ניקיון stdout. זו חסימת API בתהליך הבדיקה, לא הוכחה לחומת אש ברמת מערכת ההפעלה. יצירת קישור קובץ ב־Windows עשויה להידלג אם חסרה הרשאת מערכת; בדיקת junction נפרדת נשארת פעילה.
