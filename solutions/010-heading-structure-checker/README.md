# בודק מבנה כותרות נגיש למסמכי Markdown

שרת MCP מקומי שמאתר דילוגים ברמות כותרת, חוסר או ריבוי H1, כותרות ריקות וכותרות כפולות באותה רמה. מתאים לכותבי תיעוד, בלוגים ואתרים סטטיים. הדוח מסייע לתקן ניווט במסמך לפני פרסום, אך אינו מהווה אישור נגישות.

## הפעלה

נדרשים Node.js בגרסה 20 ומעלה והתלויות המדויקות ב־`package.json`. השרת אינו מתקין דבר ואינו זקוק לרשת בזמן שימוש. אחרי שהתלויות זמינות:

```sh
npm run check
npm run build
npm test
node dist/src/server.js --root C:/your-project/docs
```

הגדירו בלקוח MCP פקודת `node` עם הנתיב המוחלט לשרת, ואז `--root` ונתיב מוחלט לתיקיית המסמכים המקומית. התקשורת היא דרך stdio בלבד. כל נתיב בכלי הוא יחסי לשורש הזה. הנתיב `.` מציין את השורש. כתובות URL ונתיבים שעולים מעל השורש נדחים.

## כלים

| כלי | קלט לדוגמה | תוצאה |
|---|---|---|
| `list_markdown_files` | `{ "directory": ".", "recursive": false }` | רשימה ממוינת של קובצי `.md` ו־`.mdx` |
| `scan_heading_structure` | `{ "paths": ["README.md"] }` | סיכום H1 וממצאים לכל קובץ |
| `scan_heading_structure` | `{ "directory": ".", "recursive": true }` | סריקת תיקייה ותתי־תיקיות |

אין להעביר `paths` ו־`directory` יחד. ברירת המחדל ל־`recursive` היא `false`. כותרות ATX עם סולמיות וכותרות setext עם קו `===` או `---` נתמכות. מספרי השורות מתחילים ב־1, גם בקובצי CRLF. `related_lines` מציג את שורת הכותרת הקודמת בדילוג, את שורת ההופעה הראשונה בכפילות, או את כל שורות H1 במקרה של ריבוי. `h1_count` ו־`h1_lines` מופיעים לכל קובץ שנקרא.

## מגבלות והתנהגות

`MAX_RETURNED_ITEMS` הוא 200. כל קריאה מחזירה לכל היותר 200 קבצים ו־200 ממצאים. גם רשימות שורות H1 מוגבלות ל־200; `h1_count` נשאר הספירה המלאה. `truncated: true` מציין שנמצאו יותר; `finding_count` נשמר לכל קובץ שנסרק. טקסט הכותרת בממצא כפילות מוגבל ל־160 תווים. סריקת תיקייה עוצרת גם אחרי 20,000 רשומות או 2,000 תיקיות כדי למנוע עבודה בלתי מוגבלת. קובץ מוגבל ל־2,000,000 בתים. קובצי UTF-8 פגומים או בינריים מופיעים ב־`skipped` עם `UNSUPPORTED_ENCODING_OR_BINARY`; קובץ גדול מופיע עם `FILE_TOO_LARGE`. נתיב לא קיים מופיע ב־`errors` עם `NOT_FOUND`. תיקייה ריקה מחזירה מערכים ריקים וספירות אפס.

התוצאה ממוינת באופן יציב לפי נתיב ושורה. אין שמירת מצב בין קריאות. הסריקה מתעלמת מתיקיות וקבצים מוסתרים, `node_modules`, קישורים סמליים וגדרות קוד. כותרות ב־Markdown מורכב במיוחד, רכיבי MDX שנוצרים בזמן ריצה וקינון HTML אינם מפוענחים במלואם. כותרות כפולות הן סימן לבדיקה אנושית, לא בהכרח שגיאה.

השרת קורא קבצים בלבד ואינו כותב, מוחק, שולח נתונים או מפעיל טלמטריה. שני הכלים מסומנים כקריאה בלבד, לא הרסניים, אידמפוטנטיים וללא גישה לעולם חיצוני. תוכן מסמך מטופל כנתונים, לא כהוראות. בדיקות נתיב וקישור מגבילות מעבר מחוץ לשורש, אך אינן תחליף לבידוד מערכת הפעלה כאשר תהליך אחר משנה את העץ במקביל. בחרו תיקייה מקומית יציבה שבשליטתכם.

ארבעה קובצי בדיקות כוללים פרסר, גילוי קבצים, גבולות ובטיחות, וחיבור MCP אמיתי דרך stdio עם חסימת ממשקי רשת נפוצים בתהליך השרת. `evaluations.xml` מכיל עשר דוגמאות פלט יציבות.
