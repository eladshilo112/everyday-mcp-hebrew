# 002, מאתר קבצים כפולים

כלי MCP מקומי שמזהה קבצים זהים לפי התוכן שלהם, לא רק לפי השם או הגודל. הוא מחזיר דוח מסודר והצעת ניקוי ידנית, בלי למחוק, להעביר, לשנות או לשנות שם של שום קובץ.

## למי זה עוזר

למי שמנהל תיקיית הורדות, ארכיון אישי או תיקיית עבודה ורוצה להבין איפה נשמרו עותקים זהים, בלי לחבר חשבון ובלי להעלות מידע לענן.

## שורה תחתונה

השרת קורא את התיקייה שבחרתם, מחשב לכל קובץ גיבוב SHA-256 ומקבץ רק קבצים בעלי תוכן זהה. כל התוצאות נשמרות בזיכרון של תהליך השרת בלבד ונעלמות עם סגירתו.

## שלושת הכלים

### `scan_directory`

סורק נתיב מקומי שהמשתמש מספק. ברירת המחדל היא עומק מרבי של 16 תיקיות משנה, עד 10,000 קבצים רגילים ועד 100 MiB לקובץ.

הכלי:

* מחזיר נתיבים יחסיים וקבועים בתוך התיקייה הנסרקת.
* מדלג על קישורים סמליים ואינו עוקב אחריהם.
* מדלג על קבצים שחורגים ממגבלת הגודל ומדווח עליהם.
* עוצר עם שגיאה מובנית וברורה אם נחצית מגבלת מספר הקבצים.
* מחזיר שגיאה מובנית עבור נתיב חסר, נתיב שאינו תיקייה או בעיית הרשאות.

### `find_duplicates`

מקבל מזהה סריקה, או משתמש בסריקה המוצלחת האחרונה באותו תהליך. הוא מקבץ קבצים לפי SHA-256, ממיין את הנתיבים בסדר קבוע ומחשב כמה בתים ניתן לפנות אם שומרים עותק אחד מכל קבוצה.

### `suggest_cleanup`

מציע לשמור את הנתיב הראשון בסדר המיון ולבדוק ידנית את שאר העותקים. זו הצעה בלבד. אין בכלי פעולת מחיקה, העברה, שינוי או שינוי שם.

## התקנה ובנייה

## דוגמת בקשה

> סרוק את התיקייה המקומית שבחרתי. הצג את קבוצות הקבצים הזהים לפי תוכן, ואז הצע תוכנית ניקוי ידנית בלבד. אל תמחק, אל תעביר ואל תשנה קבצים.

סדר העבודה הנכון הוא:

1. קריאה ל־`scan_directory` עם הנתיב והמגבלות הרצויות.
2. קריאה ל־`find_duplicates` עם `scan_id` שהתקבל.
3. קריאה ל־`suggest_cleanup` עם אותו `scan_id`.
4. בדיקה אנושית של כל הצעה לפני כל פעולה חיצונית.

## פרטיות ובטיחות

* אין גישה לרשת, טלמטריה, אנליטיקה או דיווח שימוש.
* אין צורך בחשבון, מפתח API, סיסמה או הרשאה לשירות ענן.
* תוכן הקבצים נקרא רק לצורך חישוב SHA-256 ואינו מוחזר בתוצאה.
* אין כתיבת מטמון. מצב הסריקה נשמר בזיכרון בלבד, עד 16 סריקות מוצלחות אחרונות.
* כל פעולות הכלים הן קריאה בלבד. אין מחיקה אוטומטית ואין פעולת ניקוי נסתרת.
* שינוי קובץ במהלך הסריקה גורם לדילוג בטוח עליו במקום להציג תוצאה לא יציבה.
* נתיבים יחסיים מפחיתים תלות בתיקיית העבודה ומאפשרים דוח עקבי.

## מגבלות ידועות

* גיבוב קבצים גדולים צורך זמן קריאה בהתאם לגודל הכולל, במסגרת התקרות שהוגדרו.
* קבצים שאין לתהליך הרשאת קריאה עבורם מסומנים כפריטים שדולגו.
* מצב הסריקה אינו משותף בין תהליכים ואינו נשמר לאחר סגירת השרת.
* SHA-256 מזהה תוכן זהה. הוא אינו מנסה לזהות תמונות דומות או מסמכים דומים מבחינה חזותית.

## בדיקות

חבילת הבדיקות כוללת סריקות אמיתיות בתיקיות זמניות, שגיאות נתיב מובנות, מגבלות גודל ועומק, קישור סמלי, סדר דטרמיניסטי, הוכחת אי שינוי קבצים ובדיקת אינטגרציה שמפעילה את השרת כלקוח MCP אמיתי דרך stdio.

## English quick start

This is a deterministic, local, read-only stdio MCP server. Build with `npm run build`, start with `npm start`, call `scan_directory`, then `find_duplicates`, then `suggest_cleanup`. It hashes bounded local files with SHA-256, skips symlinks and oversized files, keeps scan state only in memory, performs no network activity, and never deletes or modifies files.
