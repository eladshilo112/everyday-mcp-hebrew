# 005, בודק בהירות טקסט לתקשורת

שרת MCP מקומי שמנתח טקסט לפי כללים קבועים ומסמן משפטים ארוכים, ניסוחים סבילים ומונחים מסובכים. אפשר למסור טקסט ישירות או לבחור קובץ טקסט מקומי, בלי לשנות את המקור ובלי לשלוח תוכן לשום שירות חיצוני.

## שורה תחתונה

מקבלים ציון בהירות בין `0` ל־`100`, תווית בעברית ורשימת בעיות מסודרת שאפשר להפוך לצעדי עריכה ידניים. אותה גרסת שרת מחזירה תמיד אותה תוצאה עבור אותו טקסט, ללא רשת, טלמטריה או חשבון.

## שני הכלים

### `check_clarity`

מנתח את המקור ומחזיר את `clarity_score`,‏ `clarity_label`, ממוצע אורך המשפטים, ספירות לפי סוג, מספר הממצאים ורשימת `complex_sentences` של המשפטים שסומנו. מוחזרים עד `500` משפטים מסומנים, לצד `complex_sentence_count`,‏ `complex_sentences_returned` ו־`complex_sentences_omitted` שמבהירים את הסכום המלא.

### `list_issues`

מחזיר עד `500` בעיות מפורטות בסדר יציב. כל רשומה כוללת `line`,‏ `type`,‏ `type_he`,‏ `sentence`,‏ `word_count`,‏ `match` ו־`message_he`. קטע המשפט בשדה `sentence` מוגבל ל־`240` תווי Unicode. השדות `issue_count`,‏ `issues_returned` ו־`issues_omitted` מבדילים בין הסכום המלא לבין הרשימה המוחזרת.

שני הכלים מחזירים טקסט קריא בשדה `content` ואובייקט מלא בשדה `structuredContent`.

## חוזה הקלט

בכל קריאה חובה לספק בדיוק אחד משני השדות:

| שדה | שימוש | כללים |
|---|---|---|
| `text` | טקסט שנמסר ישירות | מחרוזת שאורכה עד `200,000` תווי Unicode |
| `file_path` | נתיב לקובץ טקסט מקומי | עד `4,096` תווים, לקובץ UTF-8 רגיל שנקרא בלבד, ואורכו לאחר הקריאה מוגבל ל־`200,000` תווי Unicode |

אסור לספק את שני השדות יחד ואסור להשמיט את שניהם. מצב כזה מחזיר `ok: false`,‏ `isError: true` ואת הקוד `invalid_input`. נתיב יחסי נפתר מתיקיית העבודה של השרת. שגיאת קריאה צפויה של קובץ מוחזרת כשגיאה מובנית ללא stack trace. נתיב רשת, כתובת URL או נתיב שאינו קובץ רגיל נדחים. גם רכיב נתיב אחרון שהוא קישור סמלי בזמן הבדיקה נדחה.

דוגמת טקסט ישיר:

```json
{
  "text": "כתבו משפט קצר, ישיר וברור."
}
```

דוגמת קובץ מקומי:

```json
{
  "file_path": "C:\\Users\\me\\Documents\\draft.txt"
}
```

## הכללים הדטרמיניסטיים

השרת אינו משתמש במודל שפה. הוא מפעיל את אותם כללים קבועים בכל קריאה:

1. `long_sentence`, משפט שיש בו יותר מ־`40` מילים. משפט בן `40` מילים אינו מסומן.
2. `passive_voice`, התאמה לאחת מתבניות הסביל המקובעות. בין הדוגמאות: `נכתב`, `בוצע`, `אושר`, צירוף עם `על ידי`, או באנגלית צורה של `be` לפני פועל מתאים.
3. `complex_term`, הופעה של מונח מהרשימה המקובעת: `אופטימיזציה`, `אימפלמנטציה`, `אינטרדיסציפלינרי`, `קונסולידציה`, `מתודולוגיה`, `סינרגיה`, `סקיילביליות`, `פרדיגמה`, `facilitate`, `leverage`, `methodology`, `operationalize`, `optimization`, `paradigm`, `scalability`, `synergy`, `utilize`, `value add`.

נקודה, סימן שאלה, סימן קריאה, שלוש נקודות או ירידת שורה מסיימים משפט. ההתאמה למונחים באנגלית אינה תלוית רישיות. הממצאים מסודרים לפי שורת המקור והמיקום בתוך המשפט, ובאותו מיקום לפי הסדר `long_sentence`,‏ `passive_voice`,‏ `complex_term`. חזרות נפרדות יוצרות ממצאים נפרדים.

## חישוב הציון

לטקסט שיש בו לפחות מילה אחת, הציון מתחיל ב־`100` ומחושב כך:

```text
A = min(30, max(0, round(average_sentence_length - 25)))
score = max(0, 100 - 12L - 8P - 4C - A)
```

`L` הוא מספר ממצאי `long_sentence`,‏ `P` הוא מספר ממצאי `passive_voice`,‏ `C` הוא מספר ממצאי `complex_term`, ו־`A` הוא קנס אורך ממוצע שמוגבל ל־`30` נקודות. ממוצע אורך המשפטים מוחזר בדיוק של ספרה עשרונית אחת. טקסט שאין בו מילים מקבל ציון `0`.

התווית נקבעת לפי הציון:

| מצב | תווית |
|---|---|
| אין מילים | `ללא טקסט` |
| ציון `80` ומעלה | `ברור` |
| ציון `60` עד `79` | `דורש שיפור` |
| ציון נמוך מ־`60` | `קשה לקריאה` |

הציון הוא כלי איתור עקבי, לא שיפוט של איכות, עובדות, טון או התאמה לקהל.

## פלט הכלים

`check_clarity` מציג את ציון הבהירות, התווית, מספר התווים, המילים והמשפטים, אורך המשפט הממוצע, מספר הממצאים והחלוקה לשלושת הסוגים. `list_issues` מציג את הממצאים המפורטים באותו סדר יציב. הספירות תמיד מתייחסות לכל הקלט, גם כאשר רשימת הפלט נחתכת אחרי `500` פריטים. טקסט קצר שיש בו מילים ואין בו בעיות מקבל ציון `100` ורשימה ריקה. טקסט ריק מקבל ציון `0` ותווית `ללא טקסט`.

הפלט אינו משכתב את הטקסט ואינו טוען שהצעה כלשהי יושמה. מומלץ לעבור ידנית על ההקשר לפני שינוי ניסוח.

## התקנה, בדיקה ובנייה

נדרשת סביבת Node.js בגרסה 20 ומעלה.

```bash

npm run check

npm test
```

השרת ממתין לקריאות MCP דרך stdin ומחזיר תשובות דרך stdout.

## פרטיות ובטיחות

* השרת מיועד לקבצים בכונן מקומי ופועל בקריאה בלבד.
* אין כתיבה, עריכה, החלפה, העברה, שינוי שם או מחיקה של תוכן קבצים. מערכת ההפעלה עשויה לעדכן זמן גישה בעת קריאה, בהתאם להגדרות הכונן.
* בקוד אין לקוח רשת, טלמטריה, חשבון, מפתח API או פרטי התחברות. צורות נתיב של URL ו־UNC נדחות לפני הקריאה.
* כונן ממופה או מערכת קבצים מרוחקת שמחוברת ככונן מקומי אינם ניתנים לזיהוי אמין בכל מערכת הפעלה. יש לבחור קובץ שנמצא בפועל בכונן מקומי.
* טקסט ונתיבי קבצים אינם מועלים ואינם נשמרים מחוץ לזיכרון התהליך הדרוש לקריאה.
* הכלים מחזירים אבחון והצעות בלבד. הם אינם מבצעים עריכה אוטומטית.

## מגבלות ידועות

* הבדיקה מבוססת על התאמות קבועות, ולכן ייתכנו סימונים עודפים או החמצות.
* זיהוי צורת סביל אינו ניתוח דקדוקי מלא.
* רשימת המונחים המסובכים סגורה למונחים המתועדים למעלה ואינה מסיקה מונחים לפי הקשר.

## English quick start

Build with `npm run build`, start the local stdio server with `npm start`, and call `check_clarity` or `list_issues` with exactly one of `text` or `file_path`. Input is limited to 200,000 Unicode code points, and each detailed result list is capped at 500 items with explicit total and omitted counts. The server applies fixed long-sentence, passive-phrase, and complex-term rules, returns readable text plus `structuredContent`, and contains no network client, telemetry, account access, or file-writing operation.
