# 004, מנתח שטח דיסק מקומי

שרת MCP מקומי שממפה את צריכת האחסון של תיקייה ומציג את הקבצים והתיקיות הגדולים ביותר. הסריקה קוראת מטא־דאטה בלבד, אינה פותחת את תוכן הקבצים ואינה משנה דבר.

## שורה תחתונה

מקבלים תמונת מצב ברורה ודטרמיניסטית של גודל לוגי בבייטים, כולל סיכום, דירוג ואזהרות על נתיבים שלא נסרקו. השרת פועל בתעבורת stdio, ללא רשת, חשבון או טלמטריה.

## שלושת הכלים

### `scan_directory`

סורק תיקייה מקומית ושומר בזיכרון את תוצאת הסריקה המוצלחת האחרונה.

| שדה קלט | חובה | ברירת מחדל | כללים |
|---|:---:|---|---|
| `path` | כן | אין | נתיב לתיקייה מקומית קיימת. נתיב יחסי נפתר מתיקיית העבודה של השרת |
| `max_depth` | לא | `16` | מספר שלם בין `0` ל־`64` |
| `exclude_patterns` | לא | `[".git", "node_modules"]` | עד 32 תבניות glob תלויות־רישיות. מערך שסופק מחליף את ברירות המחדל, גם אם הוא ריק |

דוגמה:

```json
{
  "path": "C:\\Users\\me\\Documents",
  "max_depth": 16,
  "exclude_patterns": [".git", "node_modules"]
}
```

### `list_largest_items`

מחזיר פריטים מהסריקה המוצלחת האחרונה, לפי גודל מהגדול לקטן.

| שדה קלט | חובה | ברירת מחדל | כללים |
|---|:---:|---|---|
| `top_n` | לא | `10` | מספר שלם בין `1` ל־`100` |
| `item_type` | לא | `all` | אחד מהערכים `all`, `file`, `directory` |

דוגמה:

```json
{
  "top_n": 20,
  "item_type": "file"
}
```

הנתיבים בדירוג יחסיים לשורש שנסרק ומשתמשים תמיד במפריד `/`. השדה `root_path` מכיל את הנתיב המוחלט והקנוני של שורש הסריקה. כאשר לשני פריטים אותו גודל, הנתיב היחסי קובע את הסדר באופן לקסיקוגרפי יציב שאינו תלוי בשפת מערכת ההפעלה. כל פריט כולל גם שדה `complete` שמבהיר אם גודלו חושב במלואו.

### `get_scan_summary`

מחזיר את סיכום הסריקה המוצלחת האחרונה ששמורה בזיכרון התהליך. הכלי אינו מקבל פרמטרים:

```json
{}
```

הסיכום כולל את הגודל הכולל בבייטים, מספר הקבצים, מספר התיקיות ומידע על נתיבים שדולגו. סריקה שנכשלה אינה מחליפה סריקה מוצלחת קודמת. הפעלה מחדש של השרת מנקה את המצב שבזיכרון.

כל שלושת הכלים מחזירים גם טקסט קריא בשדה `content` וגם אובייקט מלא בשדה `structuredContent`.

## איך מחושב הגודל

* גודל קובץ הוא הגודל הלוגי בבייטים שמדווח במטא־דאטה של מערכת הקבצים.
* גודל תיקייה הוא סכום הגדלים הלוגיים של הקבצים שביקרה בהם הסריקה מתחתיה.
* הגודל אינו מדידה של בלוקים שהוקצו בפועל. קבצים דלילים, דחיסה ומאפייני מערכת הקבצים עשויים לגרום להבדל בין הגודל הלוגי לבין השטח הפיזי.
* תבניות ההחרגה מגדירות מראש את היקף הסריקה המבוקש, ולכן פריט אינו מסומן כחלקי רק מפני שצאצא מוחרג. לעומת זאת, עומק מרבי, שגיאת קריאה, קישור סמלי או דילוג מחזורי עשויים ליצור גודל חלקי שאינו כולל את מה שלא נסרק.

## סדר קבוע ומגבלות זיכרון

המעבר על העץ מזרים רשומות תיקייה ואינו מחזיק רשימת קבצים מלאה. זיהוי מחזורים שומר רק את זהויות תיקיות האב הפעילות, עד לעומק המרבי. כל האוספים שנחשפים בפלט ממוינים בסדר אורדינלי יציב. הדירוג ממוין לפי גודל יורד ואחריו לפי נתיב יחסי. הפלט אינו כולל חותמות זמן ואינו משתמש במיון תלוי־מיקום או בשפה מקומית, ולכן אותו עץ קבצים יוצר אותו פלט מסודר.

לצורך הדירוג נשמרים לכל היותר 100 קבצים ו־100 תיקיות. פירוט האזהרות מוגבל ל־200 רשומות מסודרות, כדי שעץ גדול או חסום לא ייצור פלט וזיכרון בלתי מוגבלים. `warning_count` סופר את כלל האזהרות ו־`warnings_omitted` מציין כמה מהן לא נכללו בפירוט.

## דילוגים ואזהרות

* רכיב שורש סופי שהוא קישור סמלי נדחה. קישורים סמליים שנמצאים מתחת לשורש הקנוני אינם נעקבים ומדווחים בקוד `SYMLINK_SKIPPED`. אם רכיב אב בנתיב השורש הוא קישור סמלי, הנתיב נפתר תחילה לשורש הקנוני שהמשתמש ביקש במפורש.
* זיהוי מחזור מדלג על הנתיב המחזורי ומדווח בקוד `CYCLE_SKIPPED` במקום להיכנס ללולאה.
* כשל הרשאה או כשל קריאת מטא־דאטה נרשם לכל נתיב בנפרד בקוד `PERMISSION_DENIED` או `READ_ERROR`, ושאר העץ ממשיך להיסרק.
* הגעה ל־`max_depth` מדלגת על הצאצאים העמוקים יותר ומדווחת בקוד `MAX_DEPTH_REACHED`. הסיכומים והגדלים במקרה כזה חלקיים ומכילים רק פריטים שבוקרו בפועל.
* נתיב שנפתר מחוץ לשורש או סוג פריט שאינו נתמך מדולגים בקוד `OUTSIDE_ROOT_SKIPPED` או `UNSUPPORTED_TYPE`.
* שגיאות ברמת פעולת הסריקה מוחזרות בקודים `invalid_path`, `not_found`, `not_directory`, `root_symlink`, `permission_denied`,‏ `size_overflow` או `scan_failed`. קריאה לכלי תלוי־סריקה לפני סריקה מוצלחת מחזירה `no_scan`.

## התקנה, בדיקה ובנייה

נדרשת סביבת Node.js בגרסה 20 ומעלה.

```bash
npm install --ignore-scripts
npm run check
npm run build
npm test
```

החבילה משתמשת רק בגרסאות התלויות המקובעות ב־`package.json`. אין סקריפטים שפועלים בזמן ההתקנה ואין `package-lock.json` בקוד המקור.

## הפעלה

לאחר הבנייה:

```bash
npm start
```

השרת ממתין לקריאות MCP דרך stdin ומחזיר תשובות דרך stdout. את תיקיית הסריקה מוסרים בשדה `path` של `scan_directory`.

## פרטיות ובטיחות

* אין כתיבה, עריכה, העברה או מחיקה של קבצים ותיקיות.
* אין קריאה של תוכן קבצים. נקראים רק שמות, סוגים, גדלים ומטא־דאטה שנדרש לניווט בטוח.
* אין פעילות רשת, טלמטריה, חשבון, מפתח API או פרטי התחברות.
* אין פעולה אוטומטית לפינוי מקום. הדוח הוא מידע בלבד והמשתמש מחליט בנפרד מה לעשות.

## מגבלות ידועות

* זהו מנתח תיקיות, לא כלי למדידת מחיצות, מכסות, שטח פנוי או בלוקים פיזיים.
* קישורים סמליים אינם נכללים בגודל היעד שלהם.
* תיקיות שהוחרגו אינן חלק מהיקף הסריקה המבוקש. נתיבים שנחסמו בהרשאה או נמצאים מעבר לעומק המרבי יוצרים סכומים חלקיים ומסומנים בהתאם.
* שינויים שמתרחשים בעץ בזמן הסריקה עשויים להשפיע על אותה סריקה. מומלץ לסרוק שוב לאחר העברה או יצירה של קבצים.
* נשמרת רק הסריקה המוצלחת האחרונה ורק כל עוד תהליך השרת פועל.

## English quick start

Run `npm run build`, then start the stdio server with `npm start`. Call `scan_directory` with a local directory path, optionally set `max_depth` or replacement `exclude_patterns`, then call `list_largest_items` or `get_scan_summary`. Every tool returns readable text and `structuredContent`. The server reads filesystem metadata only, keeps bounded in-memory rankings, and performs no writes, deletions, network calls, telemetry, or account access.
