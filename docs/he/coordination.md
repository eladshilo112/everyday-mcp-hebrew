# חוזה התיאום של המאגר

המטרה של החוזה היא שכל שיחה, סוכן וכלי ידעו מה המצב בלי להסתמך על זיכרון אנושי או על מזהי שיחות פרטיים.

## מי עושה מה

* **שיחת הבעלים** קובעת את גבולות המשימה ואת הפעולה הבאה.
* **Claude** מתכנן ובודק באופן עצמאי. הוא מקבל רק הקשר ממוקד ואת הדלתא הרלוונטית.
* **Codex** מממש בשכפול זמני ומוגבל. הוא אינו מבצע Git או GitHub.
* **שערים דטרמיניסטיים** מריצים בנייה, בדיקות, סריקות סודות, מדיניות תוכן וגבולות דלתא.
* **הרץ המקומי** הוא הבעלים היחיד של יצירת ענף, Pull Request ומיזוג מבוקר.

אין שני כותבים לאותו נתיב באותה ריצה. עבודה מקבילית מותרת רק כאשר לכל סוכן יש קבצים נפרדים או כאשר הוא במצב קריאה בלבד.

## מקור אמת לכל מצב

לכל ריצה יש מזהה `run_id` יחיד. הוא מפתח הסנכרון בין השיחה, ההרצה והראיות.

* `run-manifest.json` תחת `%LOCALAPPDATA%\EverydayMcpHebrew\runs\<run-id>` הוא מצב ההרצה החי: שלב, סטטוס, בעלים, פעולה הבאה וארטיפקטים.
* `run-report.json` הוא דוח הראיות: תוצאות שערים, שימוש בהקשר, backend, ענף ו־Pull Request.
* Git, CI ו־Pull Request הם מקור האמת לפרסום. קובץ מקומי לבדו אינו הוכחה שפורסם דבר.
* `local-handoff.md` מתאר את החוזה הציבורי, אך אינו מכיל מזהי שיחות, טוקנים או מידע פרטי.

הארטיפקטים מקבלים נתיבים יחסיים בלבד ובמידת האפשר גם SHA-256. פרומפטים גולמיים, stderr, פרטי התחברות ומזהי שיחות נשמרים מקומית בלבד ואינם נכנסים ל־Git.

## Graphify וחיסכון בטוקנים

Graphify הוא שכבת ניווט ודחיסת הקשר, לא מקור סמכות. הוא מופעל לפני התכנון, לפני המימוש ואחרי המימוש, וכל שאילתה עוברת תקציב תווים קשיח. בדוח נשמרים גודל הקשר ואומדן טוקנים, כאשר אומדן מסומן כאומדן ולא כמדידה.

## מחזור חיים

השלבים החוקיים הם: `initialized`, `preflight`, `planning`, `implementation`, `validation`, `review`, `publication`, `completed` או `failed`.

ריצה כפולה לאותו תאריך ירושלים מסתיימת ב־`duplicate_date_noop`. כשל בכל שער עוצר את הפרסום ושומר את תיק הראיות המקומי לאבחון. אין force push ואין שינוי בעותק העבודה האישי.

## סנכרון עם שיחות Codex

אפשר להשתמש ב־sections, projects ו־artifacts של Codex כדי לסדר את השיחות ואת ה־Pull Request, אך המאגר אינו שומר את מזהי השיחות. אם שיחה חדשה צריכה להמשיך ריצה, מעבירים לה את `run_id`, קוראים את ה־manifest וה־report מהמחשב, ומאמתים מחדש את מצב GitHub. כך השיחה נשארת שכבת תיאום, ולא הופכת למקור מצב מתחרה.
